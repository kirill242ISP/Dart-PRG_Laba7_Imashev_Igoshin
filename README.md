# Dart RPG Battle

Консольная RPG-битва на Dart, демонстрирующая наследование, абстрактные классы, переопределение методов и полиморфизм.

## Как запустить

1. Клонировать репозиторий:
   ```bash
   git clone <url>
   ```

2. Перейти в папку:
   ```bash
   cd lab_rpg_ivanov
   ```

3. Установить зависимости:
   ```bash
   dart pub get
   ```

4. Запустить:
   ```bash
   dart run
   ```

## Управление

- Введите имя персонажа (или оставьте пустым — будет `Герой`).
- Выберите класс: `1` — Воин, `2` — Маг, `3` — Лучник.
- После боя можно сыграть ещё раз, введя `да`.

## Что изучили

- Наследование через `extends` и вызов конструктора родителя через `super`.
- Абстрактные классы и абстрактные методы — контракт для наследников.
- Переопределение методов через `@override` и вызов родительской реализации через `super.method()`.
- Полиморфизм: переменная типа `Character` может хранить любого наследника.
- Работа с `Random` из `dart:math` для генерации урона и критических ударов.

## Ответы на вопросы

1. **Что такое абстрактный класс? Почему нельзя написать `Character()` напрямую?**
   Абстрактный класс — это шаблон, который не предназначен для создания экземпляров. Он описывает общий контракт (поля и методы) для наследников. Нельзя создать `Character()`, потому что у него есть абстрактные методы без реализации — Dart не знает, что должен делать `attack()`. Конкретику задают наследники: `Warrior`, `Mage`, `Archer`.

2. **Зачем нужен `super` в конструкторе наследника? Что будет, если его убрать?**
   `super(...)` вызывает конструктор родителя, чтобы инициализировать унаследованные поля (`name`, `hp`, `maxHp`). Если его убрать, компилятор выдаст ошибку: родительский конструктор требует обязательных параметров. Dart не может создать объект наследника, не инициализировав поля родителя.

3. **В чём разница между `@override` у `attack()` в `Warrior` и `takeDamage()` в `Warrior`?**
   `attack()` в родителе — абстрактный (без тела), поэтому `Warrior` обязан его реализовать. `takeDamage()` в родителе уже имеет реализацию, но `Warrior` переопределяет его, чтобы добавить логику брони, и вызывает `super.takeDamage(reduced)` для базового поведения. В обоих случаях `@override` защищает от опечаток: если метода нет в родителе — компилятор сообщит об ошибке.

4. **Функция `fight(Character a, Character b)` не знает, кто реально придёт. Как называется эта концепция и где вы её видели во Flutter?**
   Это **полиморфизм**. Во Flutter любая функция, принимающая `Widget`, работает с `Text`, `Column`, `ElevatedButton` — любым наследником. Например, `build(BuildContext context)` возвращает `Widget`, но реально возвращает конкретного наследника.

5. **Что означает `_random` с нижним подчёркиванием в классе `Character`?**
   Нижнее подчёркивание делает поле **приватным** на уровне библиотеки (файла). К нему нельзя обратиться из другого файла. Это инкапсуляция: детали реализации скрыты, наследники пользуются только публичным API (`attack()`, `takeDamage()` и т.д.).
